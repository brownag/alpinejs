library(alpinejs)

Pre-built Components and Patterns

This vignette covers alpinejs’s pre-built interactive components: accordions, modals, and tabs. These are ready-to-use patterns built on top of Alpine.js.

Accordion Component

An accordion displays collapsible panels where one or more can be open at a time.

Basic Accordion

  items = list(
    list(title = "What is Alpine.js?", content = "Alpine.js is a lightweight, rugged JavaScript framework."),

How It Works

The accordion uses Alpine.js internally:

// Generated x-data state
{
  collapsed: [false, true, true],  // which panels are open
  togglePanel(index) { 
    this.collapsed[index] = !this.collapsed[index];
  }
}

Each panel header has @click="togglePanel(index)" and each body has x-show="!collapsed[index]".

Modal Without Trigger Button

For programmatic control (e.g., triggered after a server action):

# Modal without automatic trigger
modal_component <- alpine_modal(
  trigger_label = NULL,  # No button
  title = "Processing...",
  content = "Your request is being processed. Please wait.",
  backdrop = FALSE  # No backdrop for a lighter feel
)

Transitions (x-transition)

alpine_transition() adds enter/leave animations to any element controlled by alpine_show(). Two modes are available: a built-in transition helper (fade + scale) and CSS class mode for full control with utility frameworks like Tailwind.

Built-in Transition Helper

# Default fade + scale transition
alpine_tag("div",
  alpine_tag("button", "Toggle",
    alpine_attr(`@click` = "open = !open")
  ),
  alpine_tag("div",
    style = "padding: 10px; background: #e8f4fd; margin-top: 8px;",
    "This content fades in and out."
  ) |>
    alpine_show("open") |>
    alpine_transition()
) |>
  alpine_data(open = FALSE)
#> 

#>   
#>   
This content fades in and out.

#>

Custom Duration and Opacity Only

# Opacity-only fade, 400ms
alpine_tag("div",
  alpine_tag("button", "Fade",
    alpine_attr(`@click` = "visible = !visible")
  ),
  alpine_tag("p", "Fades smoothly with no scale effect.") |>
    alpine_show("visible") |>
    alpine_transition(.opacity = TRUE, .duration = 400)
) |>
  alpine_data(visible = TRUE)
#> 

#>   
#>   
Fades smoothly with no scale effect.

Scale Transition with Custom Origin

# Scale from top, 300ms
alpine_tag("div",

  ) |>
    alpine_show("open") |>

CSS Class Mode (Tailwind-style)

For full control over transition phases, provide CSS class strings for each phase. This matches how Tailwind CSS transitions are structured:

# CSS class mode -- attach separate x-transition:phase="classes" attributes
alpine_tag("div", "Slides in") |>
  alpine_show("open") |>
  alpine_transition(
    .enter       = "transition ease-out duration-300",
    .enter_start = "opacity-0 translate-x-4",
    .enter_end   = "opacity-100 translate-x-0",
    .leave       = "transition ease-in duration-200",
    .leave_start = "opacity-100 translate-x-0",
    .leave_end   = "opacity-0 translate-x-4"
  )

Note: CSS class mode requires the CSS classes to be defined in your stylesheet (e.g., via Tailwind CSS or custom classes). The helper mode works with no extra CSS.

How Tabs Work

The tabs component uses:

// Generated x-data state
{
  activeTab: 0  // 0-indexed active tab
}

Each tab button has @click="activeTab = index" and each content panel has x-show="activeTab === index".

Tab buttons get dynamic class binding via x-bind:class to highlight the active tab.

Component Composition Pattern

Create reusable component functions:

# Reusable confirmation dialog
confirm_dialog <- function(message, trigger_label = "Confirm") {
  alpine_modal(
    trigger_label = trigger_label,
    title = "Confirmation",
    content = message,
    close_label = "Cancel"
  )
}

# Use it multiple times with distinct button labels
result <- alpine_tag("div",
  confirm_dialog("Delete this item?", "Delete"),
  confirm_dialog("Log out?", "Log Out")
)

Advanced: Data-Driven Components

Create components from data:

# Build an accordion from a data frame
faq_data <- data.frame(
  question = c("What is R?", "What is Alpine.js?", "What is alpinejs?"),
  answer = c(
    "R is a language for statistical computing...",
    "Alpine.js is a lightweight JavaScript framework...",
    "alpinejs brings Alpine.js to R..."
  ),
  stringsAsFactors = FALSE
)

# Convert to list format expected by alpine_accordion
items <- lapply(seq_len(nrow(faq_data)), function(i) {
  list(
    title = faq_data$question[i],
    content = faq_data$answer[i]
  )
})

alpine_accordion(items)

Performance Notes

  • Lightweight: All components are pure Alpine.js–no heavy dependencies
  • No Server Calls: Component state is managed client-side
  • Fast Rendering: HTML is generated once; only state changes are reactive
  • Suitable for: 100s to 1000s of items; for larger datasets, consider server-side pagination

Accessibility

alpinejs components use semantic HTML. For better accessibility:

# Add ARIA labels
alpine_accordion(
  items = list(
    list(title = "Section 1", content = "Content 1")
  ),
  alpine_attr(`x-bind:aria-expanded` = "true")  # Make dynamic for each panel
)

cat("```html\n", as.character(.), "\n```", sep="")

When to Use Pre-built Components

Good for:

  • Modals, dialogs, confirmations
  • Tabbed interfaces
  • Collapsible sections/FAQs
  • Mobile menus/dropdowns

Consider alternatives for:

  • Large tables (use DT + Shiny)
  • Real-time data (use WebSocket + other frameworks)
  • Complex workflows (use Shiny app)
